## 已测指标明细

### 1. 意图识别准确率 —— 93.3%
- 30 条 golden 用例 × 6 类别；product 8/8、tech 5/5、complaint 4/4、general 3/3、out_of_scope 5/5 全对，billing 3/5
- 两条误判（订单进度查询、退货条件咨询）落入 general_inquiry，属分类边界案例
- 安全护栏：越界拒答 5/5 命中，25 条正常请求零误拒
- 复现：`python -m evaluation.run_eval` → `evaluation/report.md`

### 2. Recall@K —— Recall@1 93.3% / Recall@3 100% / MRR 0.956
- 15 条 golden 查询，覆盖全部 6 份知识库文档，统计期望文档在 Top-K 的命中与排名
- 复现：`python -m evaluation.run_metrics_eval retrieval` → `evaluation/metrics_report.md`

### 3. 工具调用成功率 —— 选择 87.5% / 参数抽取 100%
- 8 条用例：含不存在订单的错误处理路径与"不该调工具"的反例
- 以记录器包装业务工具捕获 LLM 真实传参，同时验证工具选择与参数抽取
- 唯一失败：「耳机连不上蓝牙建工单」模型未直接调用 create_ticket（真实模型行为，可通过工具型 agent prompt 优化）
- 复现：`python -m evaluation.run_metrics_eval tool`

### 7. P95 响应延迟 —— 端到端 15.0s / 检索 184.8ms
- 端到端：均值 8.7s / P95 15.0s（本地嵌入 CPU 推理 + LLM 端点往返）
- 检索（嵌入 + FAISS，与生成分离计量）：均值 131.4ms / P95 184.8ms，已剔除首次加载模型的一次性冷启动
- 复现：`python -m evaluation.run_eval`（端到端）、`run_metrics_eval retrieval`（检索）

### 10. 回归通过率 —— 100%（40/40）
- 10 个测试文件：分类三层防御、图编译与护栏短路、转接路由与循环防护、有界工具循环（脚本化假 LLM）、检索与嵌入降级、评测指标纯函数、golden 文件校验、日志配置行为
- 全部离线设计：不依赖 API Key、不加载本地嵌入模型，CI（3 版本 Python 矩阵）直接可跑
- 复现：`python -m pytest tests/ -q`

## 待测指标：定义与测量方案

### 4. 回答质量（准确率）—— 忠实度 84.1% / 幻觉率 15.9% 已测
- 定义：回答拆分为事实性声明后，被知识库参考材料支持的声明占比；幻觉率 = 1 − 忠实度
- 实测：15 题中 14 题有效核验（1 题 judge 超时），会话串扰与元信息误判已修正
- 对疑似幻觉明细的逐条审阅：绝大多数为**从知识库参数推导出的适配建议**（如「45dB 降噪 → 适合通勤」「适合注重影音体验的用户」），并非编造参数，故 84.1% 是保守下界；真实幻觉风险集中在行业常识性外推（如同价位段价格区间）
- 复现：`python -m evaluation.run_metrics_eval faithfulness`

### 5. 任务完成率 —— 83.3%（10/12）已测
- 12 条端到端用例（关键词组 + 期望工具判定），实测端到端延迟均值 9.2s / P95 13.2s
- 2 条未完成均为真实失败模式：①「查订单」被分类边界误转综合客服（与路由评测的 billing 边界案例同源，可通过强化分类 prompt 优化）；②「耳机连蓝牙建工单」技术专家先给自助排障方案、未直接建单（可通过工具型 agent prompt 鼓励"信息充分时直接调用工具"优化）
- 复现：`python -m evaluation.run_task_eval`

### 6. 异常恢复率 —— 100%（7/7）已测
- 定义：注入异常（LLM 异常/超时、无效参数、索引缺失、嵌入不可用、越权转接、循环调用、LLM 不可用）后，系统按设计降级或自愈的比例
- 方法：`evaluation/resilience_scenarios.py` 七类故障注入场景，全部离线可执行；已并入 pytest 回归（CI 持续验证）
- 复现：`python -m evaluation.run_resilience_eval`
- 附带发现并修复：deepseek 端点的思考模式不支持强制 tool_choice，导致专家间转接静默失效——已改为 bind_tools 自愿调用模式并实测验证（2/2 场景转接正确）

### 8. 单次任务平均成本 —— ¥0.0107/次 已测
- 实测：单次任务平均输入 1886 + 输出 865 tokens，LLM 调用 2.7 次/任务，按输入 ¥2/M、输出 ¥8/M 折算约 **¥0.0107**（约一分钱）
- 最贵任务：报修 + 查订单复合诉求（7162 tokens，¥0.0235）；最便宜：越界拒答（540 tokens，¥0.0026）
- 复现：`python -m evaluation.run_cost_eval`（单价可在 .env 的 PRICE_INPUT_PER_M / PRICE_OUTPUT_PER_M 调整）→ `evaluation/cost_report.md`

### 9. 自动化测试覆盖率 —— 60% 已测
- 实测：全仓 1828 语句，覆盖 60%（pytest-cov，Python 3.10）
- 分布：config / golden_utils / log_setup / tools 100%，图编排 91%，意图分类 93%；专家模块 19-63%——未覆盖部分主要是真实 LLM 调用分支（离线设计下不可达，属预期），其行为由评测集覆盖
- 复现：`python -m pytest tests/ -q --cov=. --cov-report=term-missing`（CI 已自动执行）
